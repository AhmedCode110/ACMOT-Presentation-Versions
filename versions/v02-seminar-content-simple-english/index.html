Section I · Evaluation metrics

IoU vs NMS — What Is the Difference?

IoU · Intersection over Union

A measurement: how much two boxes overlap. One number from 0 to 1.

NMS · Non-Maximum Suppression

A process: it removes duplicate boxes. It uses IoU to see which boxes overlap too much.

Key difference: IoU measures overlap. NMS uses IoU to delete duplicate boxes.

Say: "IoU is a number that says how much two boxes overlap. NMS is a step inside the detector that uses IoU to delete duplicates."

Section I · Evaluation metrics

TP, FP, FN and TN: The Four Outcomes

FALSE POSITIVE: a box in the wrong place (IoU 0.22).

FALSE NEGATIVE: the bird is there, but no box.

OutcomeMeaning
TP · true positivea real object, found correctly
FP · false positivea box, but no real object there
FN · false negativea real object, but no box
TN · true negativeempty area, correctly left empty
A box counts as correct (TP) when its IoU with the real object is at least 0.5.
In detection, TN is almost never counted — empty background is everywhere.

Say: "There are four outcomes. The two mistakes we care about are FP, a box with no object, and FN, an object with no box."

Section II · Trackers

ByteTrack: The Baseline of This Work

Algorithm 1 · ByteTrack two-step matching
T ← empty set of tracks for each frame f in the video: D ← Detector(f) D_high ← boxes with score > τ D_low ← boxes with score ≤ τ predict every track in T (Kalman filter) match T with D_high by IoU # first pass T_left ← tracks still unmatched match T_left with D_low by IoU # second pass delete tracks unmatched for too long start a new track for each unmatched D_high box return T
Figure from the ByteTrack paper (Zhang et al., ECCV 2022).
The second pass uses weak boxes. A tiny, half-hidden car often has a low score — ByteTrack can still keep its ID.

Say: "ByteTrack matches strong boxes first, then gives weak boxes a second chance. That is why our detector confidence setting matters so much."

Section IV · The proposed framework

The AC-MOT Pipeline: What Happens Each Frame

Scene Complexity Index (SCI)

One number from 0 to 1 that says how hard the current frame is for the detector.

How to read it

  • Near 0.0 → CLEAR: open road, few large objects, good light
  • Around 0.5 → MEDIUM: some crowding or clutter
  • Near 1.0 → CROWDED: dense, tiny, dark or blurred

Computed every 10 frames on a small 25% grayscale copy, using OpenCV and NumPy on the CPU — under 0.2 ms, with no GPU time taken from the detector.

Note: the dial reads 0.63 for a crowded frame with many small objects and poor light. SCI does not detect anything itself. It only says how hard the next frame is, so the detector can be set up for it.

Say: "SCI is like a difficulty meter. Here it reads 0.63 — a hard frame."

Caveat: the 0.2 ms figure is from development timing.

Section IV · Step 1

SCI: Exact Formulas

c = min(count(B) / 30, 1) # crowd, from last frame's boxes t = count(area(b) < 32×32 for b in B) / count(B) # tiny share (0 if no boxes) e = mean(Canny(G, 50, 120)) / 255 # edge density n = 1 if mean(G) < 80 else 0 # night flag b = 1 if var(Laplacian(G)) < 180 else 0 # blur flag

B

boxes from the previous detector pass — no ground truth is used.

G

the 25% grayscale copy of the frame.

Then

SCIraw = clip(mix, 0, 1) · SCI = mean of the last 7 readings.

The five weights add up to 0.95, not 1 — they were design priorities, not a learned average. This is one reason Stage 2 re-learned them.

Section IV · Step 2

Smart Calibrator: What Moves, What Stays

Detector side · moves every frame
  • conf — the keep-or-drop line for a box
  • iou — the NMS overlap threshold
  • imgsz — the size the frame is fed in at

Passed straight into model.track(conf=, iou=, imgsz=).

Tracker side · tuned once, then frozen
track_high_thresh0.18track_low_thresh0.04
new_track_thresh0.20track_buffer45
match_thresh0.86

Written into the ByteTrack YAML. Never adaptive.

There are two different IoU values. The calibrator moves the detector's NMS threshold. The one that matches tracks to boxes is match_thresh = 0.86, and it never changes.

What NMS does

Lowering the NMS IoU makes suppression STRONGER — more overlapping boxes are deleted.

Why tighten it in hard scenes?

We already lowered confidence and raised the size, so more duplicates appear. Tightening removes them.

Say: "Only three detector settings move. The tracker settings were tuned once and then frozen. Don't mix the detector's NMS IoU with the tracker's match threshold."

Later finding: the optimizer showed this NMS direction is not always right — see Section VII.

Section VII · Why Stage 2

Why One Score Can Fool Us

MOTA adds three kinds of mistakes into one number. It cannot tell you which mistake went down and which went up.

Missed objects (FN)

A real object the tracker never found. Counted inside MOTA.

False alarms (FP)

A box where there is no real object. Counted inside MOTA.

ID switches (IDS)

The same person suddenly gets a new number. Counted inside MOTA, but easy to hide.

The trap

Find many more objects and MOTA rises — even if ID switches rise too. This is exactly what happened at A3.

Note: so in Stage 2, ID switches become a hard rule every candidate must pass, not just one part of a score.

Say: "Fewer misses can hide more ID switches inside MOTA. So we made ID switches a rule."

What Is Optuna? A Simple Picture

What it is

A free tool that tries settings for us automatically, instead of picking them by hand.

What it is not

It is not a neural network and it does not train YOLO. It only chooses numbers and checks the results.

By hand vs Optuna

By hand: try conf 0.25, then 0.30, then 0.35… and every mix with NMS and size. Too many combinations. Optuna chooses the combinations and spends more tries where results look good.

Optuna (Akiba et al., KDD 2019)

How TPE works

TPE (Tree-structured Parzen Estimator) looks at earlier trials and suggests more tries near the good ones, instead of trying blindly. A fixed seed (42) makes it repeatable.

Best = highest MOTA; ties → fewer IDS → higher HOTA → higher IDF1 → higher FPS.

Section VIII · Scope

What We Focused On and Why

A fixed detector for a fair test

YOLOv8n (FP16, Tesla T4) is the same in every run, so any gain comes from AC-MOT, not from a larger detector.

Final evaluation setup

17 VisDrone test-dev videos, plus 20 UAVDT videos with no tuning. Same filter, same hardware, same tracker for every system.

What AC-MOT really changes

SCI reads scene difficulty and adapts confidence, NMS IoU and input size. ByteTrack matching settings stay fixed.

What we did not claim

No gain from a bigger model. Deep ReID was not our claim; it is future work. The claim is adaptive control, not model size.

Conclusion: we kept the detector and tracker fixed and showed that adaptive, scene-based settings improve tracking quality at real-time speed.

Say: "The claim is narrow and clear: smart settings, not a bigger model."

Section VIII · Future work

Directions for Future Work

1 · Camera-motion compensation

The clearest next gain. It targets exactly the ID switches that adaptive input size adds.

2 · Density-gated input size

Raise the input size only when many tiny objects are present, not on SCI alone.

3 · A proper deep ReID

Replace the colour histogram with a small deep appearance model that stays real-time.

4 · SCI beyond YOLO

Drive RT-DETR or DINO with the same signal, finish the U2MOT study, and test on AU-AIR.

Note: these ideas come from what we measured, not from guesses.
