IoU vs NMS — What Is the Difference?

IoU · Intersection over Union

A number from 0 to 1 that says how much two boxes overlap:
IoU = shared area ÷ total area of both boxes

IoUWhat you seeMeaning
0the boxes do not touch — the box is wrong
0.5half of the area is shared — the usual line for a correct box
1the boxes lie exactly on top of each other — perfect

Green = real object, red = detector box. In this picture: 0.40 = poor, 0.73 = good, 0.93 = excellent — the better the boxes match, the closer IoU gets to 1.

NMS · Non-Maximum Suppression

A cleaning step inside the detector: it deletes duplicate boxes on the same object. It uses IoU to find them.

StepWhat happens · example: one car
1The detector draws 3 boxes on the car: scores 0.9, 0.8 and 0.7
2Keep the box with the highest score (0.9)
3Delete every box whose IoU with it is above the limit (for example 0.45)
Resultone car → one box

Say: "IoU is a number from 0 to 1. Zero means the two boxes do not touch at all. One means they sit exactly on top of each other. We usually call a box correct when IoU is at least 0.5."

Then: "NMS is a cleaning step inside the detector. When it draws several boxes on the same car, it keeps the one with the highest score and deletes the others that overlap it too much — and it measures that overlap with IoU."

TP, FP, FN and TN: The Four Outcomes

What it means

When we check a detector, every box and every real object ends in one of four results. Two are right, and two are mistakes.

ResultMeaning in easy words
TP · true positivea real object, and the detector found it ✓
FP · false positivea box, but nothing real is there — a false alarm ✗
FN · false negativea real object, but the detector missed it ✗
TN · true negativean empty area, correctly left empty ✓
A box counts as found when its IoU with the real object is at least 0.5. TN is almost never counted, because empty background is everywhere.
Example

FP: the box is in the wrong place (IoU 0.22)

FN: the bird is there, but it has no box

Section I · Evaluation metrics

Precision and Recall

Precision · can we trust the boxes?

Of all the boxes the detector drew, how many are correct?

High precision = very few false alarms.

Recall · did we find everything?

Of all the real objects, how many did the detector find?

High recall = very few missed objects.

Precision = TP ⁄ (TP + FP)

correct boxes ÷ all the boxes we drew

Recall = TP ⁄ (TP + FN)

correct boxes ÷ all the real objects

Example

A picture has 5 people. The detector draws 5 boxes: 4 are on people and 1 is on a shadow, and 1 person is missed.
TP (true positive) = 4 · FP (false positive) = 1 · FN (false negative) = 1 → Precision = 4 ÷ 5 = 0.80 · Recall = 4 ÷ 5 = 0.80

Why we need both: a detector that draws a box everywhere has high recall but low precision. A detector that draws only one very sure box has high precision but low recall.
Lower confidence threshold → the detector keeps more boxes → recall goes up (fewer misses), but precision often goes down (more false alarms).

Say: "Precision asks: can I trust the boxes? Of all the boxes we drew, how many are right. Recall asks: did we find everything? Of all the real objects, how many we found."

Example: "Five people, five boxes: four on people, one on a shadow, one person missed. Precision is 4 out of 5, recall is 4 out of 5 — both 0.80."

Why both: "Boxes everywhere give perfect recall but bad precision; one very sure box gives perfect precision but bad recall."

Section I · Detection metrics

Average Precision (AP) and Mean AP (mAP)

What it means

AP is one score for one class, for example “car”: how precise the detector stays while it finds more and more cars. mAP is the average AP over all classes.

How to read the curve

Recall goes to the right, precision goes up. A good detector keeps precision high even when recall is high, so the area under the curve is big. That area is AP, from 0 to 1.

Example

Car AP = 0.90 and person AP = 0.80 → mAP = (0.90 + 0.80) ÷ 2 = 0.85

AP and mAP judge the detector only. They say nothing about keeping IDs over time.
Curve and example values: illustration

Say: "AP is the area under the precision–recall curve for one class. mAP is the average over classes: 0.90 and 0.80 give 0.85."

Section I · Tracking metrics

MOTA — Multiple Object Tracking Accuracy

What it means

MOTA says how accurate the tracking is overall. It starts from 100% and subtracts every mistake: missed objects, false boxes and ID switches. Higher is better.

MOTA = 1 − (FN + FP + IDS) ⁄ GT

all mistakes ÷ all real objects · FN = false negative (missed) · FP = false positive (false box) · IDS = identity switches · GT = ground truth (real objects)

Four people tracked with IDs 2, 3, 4 and 5.

Example · made-up numbers

4 real people (GT = 4). The tracker misses 1 (FN = 1), draws 1 false box (FP = 1) and swaps 1 ID (IDS = 1).
MOTA = 1 − (1 + 1 + 1) ÷ 4 = 0.25

Watch out: MOTA adds all mistakes together. In crowded scenes misses are far more than ID switches, so MOTA can look good while IDs still switch.

Say: "MOTA answers: how accurate is the tracking overall? Start from 100% and take away every mistake — missed objects, false boxes and ID switches — divided by the number of real objects."

Example: "Four real people, one missed, one false box, one ID switch: 1 minus 3 over 4 gives 0.25."

Identity Switches (IDS)

What it means

An identity switch happens when the tracker gives the same object a new ID number. IDS counts how many times this happens. Lower is better — 0 is perfect.

Example

Section I · Evaluation metrics

HOTA and Processing Speed

HOTA · Higher Order Tracking Accuracy

One balanced score for tracking: did we find the objects, and did we keep their IDs? Higher is better.

FPS · frames per second

How many video frames the system handles in one second. Higher is faster.

HOTA = √( DetA × AssA )

DetA (Detection Accuracy) = did we find it? · AssA (Association Accuracy) = did we keep its ID?

Example · made-up numbers: DetA 0.64 and AssA 0.36 → HOTA = √(0.64 × 0.36) = 0.48. If either part is bad, HOTA falls.
FPS ≥ 25

our real-time rule

Example: the system handles 30 frames in 1 second → FPS = 30. At 25 FPS, each frame must take less than 40 ms.

Say: "HOTA gives one balanced score for finding and linking. FPS is speed; we need at least 25 frames each second."

How ByteTrack matches, step by step
StepWhat happens in every frame
1The detector finds boxes and splits them into strong (high score) and weak (low score)
2The tracker predicts where each known object has moved (Kalman filter)

Section IV · Scene Analyzer

The Five SCI Cues

The main idea

The Scene Analyzer measures five cheap cues. Three are continuous (0 → 1) and two are binary (0 or 1).

Crowd densitycontinuousCrowd = min(previous tracked boxes ÷ 30, 1)box count from the previous frame
Tiny-object proportioncontinuousTiny = tracked boxes smaller than 32×32 ÷ all tracked boxesCOCO small-object size [1]
Edge complexitycontinuousEdge = min(edge density ÷ 0.14, 1)grayscale image + Canny edges [2]

Lowering the NMS IoU makes suppression STRONGER — more overlapping boxes are deleted.

Why Optuna Was Introduced

The main idea

The initial SCI and controller were full of manually selected values. We wanted validation performance — not our guesses — to choose them.

Chosen by hand in the first design

  • the SCI limits between easy and hard scenes
  • the detector settings for each kind of scene

The new question

“Can the relationship between scene complexity and detector settings be optimized from validation performance instead of being fully hand-designed?”

The tool

Optuna with the TPE sampler: a sequential, Bayesian hyperparameter optimization method. It is not an AI model and trains nothing — it proposes settings, reads the score, and proposes better settings next.

Optuna (Akiba et al., KDD 2019) · TPE (Bergstra et al., NIPS 2011)

How Later Trials Use Earlier Trials (TPE)

The main idea

TPE (Tree-structured Parzen Estimator) is a sequential Bayesian method: every finished trial changes where the next trial is likely to look.

1 · early trials

The first trials explore the allowed ranges.

2 · split the history

TPE separates earlier trials into a better group and the rest.

3 · propose

New values are proposed more often where the better trials were, while still exploring.

Not a grid search and not pure random search: trial 30 is influenced by trials 1–29.
A fixed random seed (42) makes the V1 search repeatable.

Tracking metrics · 2 of 5 — MOTA

MOTA: Overall Tracking Errors

What it measures

MOTA (Multiple Object Tracking Accuracy) counts all tracking errors together — misses, false boxes and ID switches — against the number of real objects.

MOTA = 1 − ( FN + FP + IDS ) ÷ GT
Our example
1 − ( 1 + 1 + 1 ) ÷ 10
↓
= 1 − 0.30 = 0.70

Practical reading

  • higher is better; 1.00 = no errors
  • one number for everything
  • it cannot tell which error happened
Tracking metrics · 3 of 5 — IDF1

IDF1: Identity Consistency

What it measures

IDF1 (Identity F1 score) checks how much of the time each person keeps the right ID. Each real person is matched to its best predicted ID over the whole video.

IDF1 = 2·IDTP ÷ ( 2·IDTP + IDFP + IDFN )
IDTP · correct-ID boxes

A ↔ ID 1 in 3 frames
B ↔ ID 2 in 4 frames

IDTP = 7
IDFP · predicted boxes not matched

10 predicted boxes − 7
(ID 3 twice, the false box)

IDFP = 3
IDFN · real boxes not matched

10 real appearances − 7
(A as ID 3 twice, B missed)

IDFN = 3
IDF1 = 14 ÷ ( 14 + 3 + 3 ) = 0.70
Tracking metrics · 4 of 5 — HOTA

HOTA: Balanced Detection and Association

What it measures

HOTA (Higher Order Tracking Accuracy) balances two questions: did we detect the objects? (DetA) and did we keep them linked correctly? (AssA).

HOTA = √( DetA × AssA )

DetA · detection

DetA = TP ÷ ( TP + FN + FP )

Example: 9 detected appearances, 1 missed, 1 false box

9 ÷ 11 ≈ 0.82

AssA · association

Person A is split into two IDs (1 and 3), so A’s association is only partly correct → AssA goes down.

If either DetA or AssA is low, HOTA is low.

The official HOTA averages over many overlap levels; this page shows the idea, not the full calculation.

Two Operating Points, Not a Winner and a Loser

V1 · quality-oriented

  • highest MOTA, HOTA, IDF1
  • more ID switches than V2
  • pick it when finding and tracking as much as possible matters most

V2 · identity / efficiency

  • fewest ID switches, fastest
  • lower quality metrics than V1
  • pick it when stable IDs and speed matter most
V1 = one objective + rulesvsV2 = maximize MOTA and minimize IDS, with an FPS constraint
V2 is not universally better than V1 — and V1 is not best on every metric. They are different points on the quality / identity / efficiency trade-off.
