## Scientific rules kept in every version
- Never invent or change results; missing values stay missing.
- Never put metrics from different experiments in one table (ablation ≠ validation ≠ test ≠ UAVDT).
- All AC-MOT results use the custom class-agnostic AC-MOT TrackEval protocol — **not** official VisDrone leaderboard results.
- V1 does not have the fewest IDS on the test set (Old AC-MOT has fewer than V1; V2 has the fewest). V2 does not beat V1 overall.
- Do not claim literature produced a constant unless it did (only 32 × 32 has that basis).

## v31 pre-Optuna screening
The V1 section distinguishes the validation screening stage from the later Optuna trials. The screening counts and
ranges are author-supplied from `defensible_acmot_3workers/`: 15 input-size values from 512 to 960 by 32, 10
confidence values from 0.05 to 0.50, 11 NMS IoU values from 0.30 to 0.80, and 25 temporal combinations (5 windows ×
5 strides). The frozen values entering Optuna are input sizes 512 / 928 / 960, confidence 0.25–0.45, NMS IoU
0.30–0.70, window 7 and stride 10. These were run on the 7 validation videos; the test set remained separate.

## v32 temporal sweep details
The temporal candidate grid in `FROZEN_TEMPORAL_CONFIG.json` contains smoothing windows **1, 3, 5, 7, 9** and
analysis strides **1, 5, 10, 15, 20**, giving all 25 Cartesian pairs. The frozen selection rule is validation-only:
keep candidates with FPS >= 25 and IDS <= the OLD-A3 reference of 271, then prefer higher MOTA, with lower IDS,
higher HOTA, higher IDF1 and higher FPS as tie-breaks. The selected pair is window 7 / stride 10 with validation
MOTA 0.18164674437597447, HOTA 0.33064013219122707, IDF1 0.36296242459481065, IDS 271 and FPS 43.947242385619134.

## v33 screening measurement explanation
The deck explicitly describes each operating sweep row as a complete validation run: hold YOLOv8n, ByteTrack,
the other detector settings and the temporal settings fixed; change one operating parameter (or one temporal pair);
run the seven validation sequences; produce detection and tracking outputs; evaluate with TrackEval; and record MOTA,
HOTA, IDF1, IDS and FPS. This is a method explanation, not a new result family.

## v34 temporal stage accounting
The 25 temporal configurations are the Cartesian product of smoothing windows **1, 3, 5, 7, 9** and analysis
strides **1, 5, 10, 15, 20**. They are a separate validation stage before the 50 V1 Optuna trials, so the combined
count is 75 validation configurations. `Optuna Trial 24` is the identifier assigned within the Optuna stage and must
not be described as the 49th configuration overall.

## v36 U2MOT transfer study
The new Section IX uses the author-supplied U2MOT transfer brief and the frozen folder
`/content/drive/MyDrive/AC-MOT-shared/FINAL_U2MOT_ACMOT_FREEZE_2026-09-14`.
The published reproduction is YOLOX-X + U2MOT, with 17 test-dev sequences and 6,635 frames.
The baseline test values are MOTA 53.9000, IDF1 69.8000, IDS 1,239, FP 41,385 and FN 63,241.
On the seven-sequence validation set, AC-MOT changed MOTA 75.1273 → 75.4738, IDF1 75.5578 → 76.5775,
IDS 1,947 → 1,908, FP 8,837 → 7,992 and FN 7,091 → 7,726. Matched speed was 3.707 → 4.663 FPS.
On final test-dev, AC-MOT changed MOTA 53.9000 → 53.7668, IDF1 69.8000 → 69.8494,
IDS 1,239 → 1,152, FP 41,385 → 40,155 and FN 63,241 → 64,801; final AC-MOT runtime was about 4.082 FPS.
The scientific wording is quality approximately preserved with fewer IDS and FP, not an overall win over U2MOT.

## v37 U2MOT SCI boundary explanation
The U2MOT transfer slide now states the exact validation labels:
SCI < 0.5185453 = Easy; 0.5185453 <= SCI < 0.5895548 = Medium; SCI >= 0.5895548 = Hard.
The boundaries come from the approximate 33rd and 67th percentiles of SCI values calculated at validation analysis
points. V1 weights and Window 7 / Stride 10 remain fixed. The U2MOT validation SCI range is minimum 0.34155,
mean 0.55452, median 0.54897 and maximum 0.72456. The old V1 limits 0.13535 / 0.28729 would place nearly all
U2MOT points in Hard because the new minimum is 0.34155.
